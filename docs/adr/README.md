# Architecture Decision Records

ADRs preserve the context, decision, and consequences of significant product or architectural choices whose rationale will be useful later. Routine implementation details do not require ADRs.

Accepted ADRs are historical records. Do not rewrite one merely because the project changes direction; create a new ADR that explicitly supersedes the earlier decision.

A small ADR may use this structure:

```markdown
# Title

- Status: Proposed | Accepted | Superseded
- Supersedes: ADR-NNN (when applicable)
- Superseded by: ADR-NNN (when applicable)

## Context

## Decision

## Consequences
```
